# Security Policy

## Supported versions

Security fixes are provided for the latest published release. Upgrade to the
latest version before reporting an issue that may already be resolved.

## Report a vulnerability privately

Do not disclose a suspected vulnerability in a public issue, discussion, pull
request, log, or diagnostic file.

Use the repository's **Security → Report a vulnerability** option to open a
private GitHub security advisory. Include:

- The affected version
- A concise description and impact
- Reproduction steps or a minimal proof of concept
- Any suggested mitigation

If private vulnerability reporting is not available, open a public issue that
only asks the maintainer to establish a private contact channel. Do not include
the vulnerability details in that issue.

Never submit passwords, tokens, cookies, private keys, API keys, private host
names, or unredacted Home Assistant diagnostics.

## Scope

Reports about unauthorized platform configuration changes, unsafe path
handling, credential exposure, bypasses of exact target rules, or incomplete
rollback are in scope. General setup questions and feature requests belong in
the regular issue tracker.
